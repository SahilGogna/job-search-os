# Job Hunter

Turns a resume into a live, scored list of matching job postings — from LinkedIn and company career sites — in a Google Sheet, plus a tailored resume PDF for every strong match and a read-only Gmail dashboard tracking what happened to each application.

## Available skills

- **`/onboard`** — one-time setup. Reads a detailed, multi-page resume and writes `context/profile.md` (full candidate context) and `configs/search.json` (derived search parameters). Also asks whether to enable Gmail application tracking (runs an initial scan if so) and handles re-onboarding when the candidate has an updated resume. Run this first if `context/profile.md` doesn't exist yet.
- **`/job-search`** — the recurring search. Requires `context/profile.md` and `configs/search.json` to already exist. Fetches LinkedIn postings (and company career sites, if `configs/companies.json` exists), scores them, pushes to Google Sheets, and generates tailored resumes for postings above the match-score threshold.
- **`/application-tracker`** — read-only Gmail scan for application status (confirmations, interviews, offers, rejections), written to a dedicated "Applications" tab, then aggregated into a private dashboard (counts + follow-up/thank-you flags) published as a Claude Artifact. Entirely independent of the job-search Sheet — never references job postings, only Gmail. Never modifies Gmail (no labels, no mutation, no drafted/sent mail), only reads.

## Sources of truth

- `context/profile.md` — everything about the candidate: identity, contact, location, full work history, education, skills, projects, leadership.
- `configs/search.json` — derived search parameters (target roles, location, seniority, skill weights, thresholds). Regenerated by `/onboard`, read by `/job-search`.
- `configs/companies.json` — optional target-company list for direct career-site fetching (Greenhouse/Lever/Workday), read by `/job-search`. Not personal data — tracked in git, unlike `configs/search.json`.
- `templates/resume_template.tex` (+ `templates/resume.cls`) — the LaTeX resume template `/job-search`'s tailoring step fills in per posting.
- `connections.md` — registry of every external system this project reaches (LinkedIn, company career sites, Google Sheets, Gmail), and whether each is a `script` (deterministic, no judgment needed) or an `mcp` connector (genuine reasoning required, e.g. classifying an email). Check this before adding a new integration — it also explains *why* each one is built the way it is.
- `decisions/log.md` — append-only record of meaningful design decisions and why they were made. Add an entry here for any non-obvious choice, not just a code comment.

## Ground rules

- Use the project venv at `.venv/`. If it doesn't exist, create it and install `requirements.txt`.
- All scripts read secrets from `.env` (`APIFY_TOKEN`, `JSON_KEY_BASE_64`, `SHEET_ID`). If any is missing, stop and tell the user — don't guess or skip silently.
- If any step in a skill fails, print the error and stop. Do not silently fall back.
- Be direct, concise, and clear. Lead with what needs action, not status updates.
